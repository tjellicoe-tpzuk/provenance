# Provenance Extension Specification

- **Title:** Provenance
- **Identifier:** <https://stac-extensions.github.io/provenance/v0.1.0/schema.json>
- **Field Name Prefix:** Provenance
- **Scope:** Item, Collection
- **Extension [Maturity Classification](https://github.com/radiantearth/stac-spec/tree/master/extensions/README.md#extension-maturity):** Proposal
- **Owner**: @tjellicoe-tpzuk

This document explains the Provenance Extension to the [SpatioTemporal Asset Catalog](https://github.com/radiantearth/stac-spec) (STAC) specification.
This extension can be used to record provenance information, such as if a specific workflow was used to 
generate the dataset, who owns the workflow and who ran this workflow to generate the provided data.

- Examples:
  - [Item example](examples/item.json): Shows the basic usage of the extension in a STAC Item
  - [Collection example](examples/collection.json): Shows the basic usage of the extension in a STAC Collection
- [JSON Schema](json-schema/schema.json)
- [Changelog](./CHANGELOG.md)

### Additional Field Information

#### provenance:date_generated

This field defines the date on which the data was generated by the workflow. 
Timestamps consist of a date and time in UTC and MUST be formatted according to RFC 3339, section 5.6. 
The temporal reference system is the Gregorian calendar. Note, this is not necessarily the same as when the data was added to the catalog.

#### provenance:workflow_used_id

This field defines the id of the workflow/process which was used to generate the data. 
This is a string that can be used to identify the workflow within the host repository. 
Note, this ID may not be unique in the host location, but this should aid in identifying 
the workflow when combined with the following attributes.

#### provenance:workflow_platform

This field defines the platform that was used to execute the workflow. 
This effectively defines the platform or organization that the data was generated by.

#### provenance:workflow_used_version

This field defines the version of the workflow that was used to generate the data, e.g. v1.0.0.

#### provenance:workflow_used_origin

This field defines the originating location of the workflow. 
This will be the location where the workflow was initially developed and from where it was shared with the wider EO community.

#### provenance:workflow_inputs

This field defines the exact inputs used when running the workflow to generate the given data. 
It includes an array of input objects, with data including input name, type and origin. 
This enables replication of workflow results, to allow validation and verification.

#### provenance:workflow_execution_duration

This field defines the time taken to run the workflow, given in seconds.

#### provenance:workflow_step_id

This field defines the step within a workflow that produced this data. 
In many cases this will be identical to the workflow ID, as it may be a final output from the workflow.

#### provenance:workflow_owner_contact

This field defines the details for the original creator, and therefore owner, of a workflow, stored in a Contact Object.

#### provenance:workflow_runner_contact

This field defines the details for the user that ran the workflow within the platform/organization 
defined in `workflow_ran_by`, stored in a Contact Object.

### Input Object

This object contains data about inputs that were passed into a workflow, including ID, type and 
any other information deemed useful to scientists.

| Field Name | Type         | Description                                                                                               |
| ---------- | ------------ | --------------------------------------------------------------------------------------------------------- |
| id         | string       | The ID of the input                                                                                       |
| type       | string       | The type of this input                                                                                    |
| value      | string\|null | The value of this input, if available, formatted as a string                                              |
| href       | string\|null | If the input should instead be provided as a file, this defines a link to the location of this input data |
| details    | string       | Any other information that should be included with the input definition                                   |

### Contact Object

This object contains details for a specific contact that is related to the data.

| Field Name    | Type   | Description                                  |
| ----------    | ------ | -------------------------------------------- |
| name          | string | The full preferred name of the contact |
| email_address | string | The email address for the contact |
| organization  | string | The organization of the contact |

### Running tests

The same checks that run as checks on PR's are part of the repository and can be run locally to verify that changes are valid. 
To run tests locally, you'll need `npm`, which is a standard part of any [node.js installation](https://nodejs.org/en/download/).

First you'll need to install everything with npm once. Just navigate to the root of this repository and on 
your command line run:
```bash
npm install
```

Then to check markdown formatting and test the examples against the JSON schema, you can run:
```bash
npm test
```

This will spit out the same texts that you see online, and you can then go and fix your markdown or examples.

If the tests reveal formatting problems with the examples, you can fix them with:
```bash
npm run format-examples
```
